# Fraud model artifacts

This directory holds the trained model (`fraud_model.joblib`) and its
metadata (`model_metadata.json`), generated by `app/ml/train.py`.

## ⚠️ This model is trained on synthetic data

There is no real historical claims dataset anywhere in this project.
`app/ml/train.py` fabricates a labeled dataset from a hand-written
"ground truth" fraud-propensity formula so there is something
trainable end-to-end — real feature engineering, a real serialized
model, real inference, real SHAP explanations. It is **not** a
substitute for training on actual claims history with known fraud
outcomes, and its risk scores should not be trusted for any real
decision as-is.

## Regenerating the model

```bash
cd ai-services
pip install -r requirements.txt
python -m app.ml.train
```

This overwrites `fraud_model.joblib` and `model_metadata.json`. The
FastAPI app loads whatever is on disk at startup (`app/ml/model_service.py`)
— restart the service after retraining.

## Retraining on real data

To move off the synthetic dataset:

1. Replace `generate_synthetic_dataset()` in `app/ml/train.py` with a
   function that loads real historical claims (with a known
   `is_fraud` outcome) and computes the same six features listed in
   `app/features.py`'s `FEATURE_ORDER` — or update both `features.py`
   and `train.py` together if the feature set changes, since they
   must stay in sync (see the module docstring in `features.py`).
2. Re-tune `risk_threshold_medium` / `risk_threshold_high` in
   `app/config.py` using validation data and business cost analysis
   (precision/recall/PR-AUC tradeoffs), not the placeholder values
   currently there.
3. Re-run `python -m app.ml.train` and check `model_metadata.json`'s
   `metrics` block before deploying the new artifact.
